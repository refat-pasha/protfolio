I build production ASP.NET Core backends with Angular front ends. The flagship is CampusConnect — a university ERP spanning seventeen modules and seven roles across a forty-three table schema, held up by a three hundred eighty-nine test suite.

The second project exists because I wanted to see what happens when fifty thousand buyers hit one endpoint inside the same second. Double-booking is prevented with SQL Server rowversion tokens rather than an in-memory lock, because an in-memory lock stops working the moment you run two API instances. 01

CampusConnect Flagship

ASP.NET Core MVC · Web API · EF Core · SQL Server · SignalR · xUnit

A university ERP built as an operating system for academia — 17 modules, 7 roles, 14 authorization policies, and an API that shares services with the MVC screens so the two cannot drift.

  • Rule engines (registration, grading, fees, scheduling, exams) as pure static classes — testable with no database and no clock.
  • Uploads hardened against stored XSS, path traversal, and extension spoofing via magic-number validation.
  • Soft deletes, audit interceptors, per-user notification state, live SignalR push.
  • Dockerized; migrations and demo seeding run on first boot.

02

Flash Sale Engine

ASP.NET Core 10 · Angular 22 · SignalR · SQL Server · Puppeteer

Cinema booking engineered for the scenario that breaks naive systems — thousands of buyers hitting one endpoint inside the same second, all fighting over the same seats.

  • Double-booking eliminated with SQL rowversion optimistic concurrency, surfaced as clean 409s.
  • Virtual waiting room: FIFO queue plus a background worker admitting batches every 10s over SignalR.
  • Queue fairness via a short-lived JWT claim, re-checked server-side — a client guard alone is bypassable.
  • Multi-seat holds in one transaction with partial success; three sweepers reclaim abandoned inventory.
  • Concurrency tests use two independent DbContexts so the database arbitrates, not a process lock.
